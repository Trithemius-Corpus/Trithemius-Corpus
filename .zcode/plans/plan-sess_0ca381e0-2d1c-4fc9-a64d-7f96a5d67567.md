## Goal
Fix the page-drift defect that caused the v2 LoRA translation lane to grade 3.49/20.8%. Root cause (confirmed): the graded run had **no output guards enabled** — `output_guard` is entirely absent from all 2,567 run records across the 6 failing works. GPT-5.5 drifted to wrong-page content and nothing caught it. The guards that *would* catch it exist but (a) were never enabled, and (b) the anchor check only fires on **zero** name hits, so drifted sermons that accidentally contain one name slip through.

## Part 1 — Strengthen `scripts/v3_output_guards.py`

**Problem with the current anchor check:** `source_anchor_missing` fires only when *zero* of 12 name/number anchors survive. Drifted prose chunks (sermons) often contain one accidental common word ("Hic" → normalized "hic") and pass.

**Add a content-overlap check** (`source_content_overlap_low`) that catches "right markers, wrong content" drift even when names don't help:

1. New helper `_source_content_overlap(source_text, output_text)`:
   - Extract Latin content words (len ≥ 5, alphabetic) from the source.
   - **Denoise long-s** (the dominant OCR artifact): convert internal `f`→`s` between vowels/iu (so `iuftitiae`→`iustitiae`, matching the cleanup the harness itself does in `clean_ocr`).
   - Extract English content words (len ≥ 5, lowercase).
   - Compute a cognate-overlap ratio: for each denoised Latin word, check whether its 4-char stem appears in any English word (catches `iustitiae`→justice, `scriptura`→scripture, `francorum`→Franks, `fidei`→faith, `romani`→Romans, `monachus`→monk).
   - Return `{"ratio": float, "hits": int, "source_words": int}`.

2. Integrate into `validate_translation_output`:
   - Always compute the overlap (cheap, no flag needed).
   - Add issue `source_content_overlap_low` to `blocking_issues` when `require_source_anchor` is true AND the overlap ratio falls below a threshold. Based on the prototype data I gathered: faithful chunks show high cognate overlap (shared Latin/English roots are dense in Trithemius's theological vocabulary), drifted chunks show near-zero. Threshold: **ratio < 0.15 with ≥ 8 source words checked** (conservative — only fires when there's enough source to judge and overlap is clearly broken).
   - Return new keys: `source_content_overlap` (the ratio), `source_overlap_hits`, so the audit and run logs carry the signal.

3. **Strengthen the existing name-anchor check**: change from "zero hits fails" to a ratio — `source_anchor_missing` fires when anchor hits/total < 0.15 (so 0–1 hits out of 12 fails, but 2+ accidental hits pass; 2/12 is still suspect for catalogue works but acceptable as a floor). Keep the current `source_anchor_unavailable` path for when there are no extractable anchors.

**Why this is safe:** Both callers (`dual_context_retranslate.py:547`, `translate_with_qwen.py:471`) read only `guard["blocking_issues"]` and serialize the whole dict. Adding keys and issue-types is non-breaking (verified — no other dict keys are read programmatically).

## Part 2 — Offline audit of all 2,567 cached chunks (the 6 failing works)

**Purpose:** before spending API budget on re-translation, measure exactly how many chunks the strengthened guards flag, and of what type. This is free (no LLM calls) — it runs the guard against already-cached translations.

**New script `scripts/audit_dual_lane.py`** (read-only — writes a report, never touches the cached translations):
- For each of the 6 failing works, read `runs.jsonl` for the authoritative chunk→pages mapping.
- For each chunk: load `full_chunk_NNNN.md` (the English), reconstruct the primary source from `_reocr/qwen3vl-4b-trithemius-q6/full.txt` using the runs.jsonl page list, run `validate_translation_output` with `require_source_anchor=True`.
- Emit a JSONL report per work: chunk, pages, blocking issues, anchor hits, overlap ratio. Plus a summary: total chunks, flagged count, breakdown by issue type (marker_drop / marker_set_mismatch / repetition_loop / preamble_leak / source_anchor_missing / source_content_overlap_low).
- Also run the audit against a control set (the 6 best S-graded works) to confirm the guards don't over-flag faithful translations — a guard that flags good chunks is worse than useless.

**Output I'll report back:** a table showing, per work, how many chunks each guard flags, and the control-set false-positive rate. This tells us the real scope of the re-run.
